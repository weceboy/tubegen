# AutoDoc v3.5 – Production Render Control

## Purpose

v3.5 adds a hard boundary between editable project state and the production renderer.
A renderer must never resolve its inputs from the live selection state at render time.
It consumes a verified production snapshot through a deterministic render plan.

## 1. Render preflight

`prepareProductionRender(projectId, snapshotId, expectedManifestHash)` performs:

1. persisted production snapshot verification;
2. manifest reconstruction from the exact snapshot lineage;
3. optional manifest-hash verification;
4. deterministic extraction of render inputs;
5. deterministic hashing of the resulting render plan.

If any verification fails, the function throws `PRODUCTION_RENDER_PREFLIGHT_FAILED` and no render plan is returned.

## 2. Immutable render boundary

The returned plan contains:

- project id
- snapshot id
- manifest hash
- scene id
- visual entity id
- visual version id
- generation attempt id
- source asset id
- object key
- asset checksum and media metadata

The renderer should consume this plan instead of querying `scene_visuals` or current selection state directly.

Changing a selected visual therefore requires a new production snapshot and a new render plan.

## 3. Hash stability

The v3.4 manifest hash contains immutable snapshot identity and content lineage only.
Mutable verification fields such as `status` and `verified_at` are excluded from the manifest hash.
This means verifying a manifest does not invalidate the manifest hash that was supplied to the renderer.

## 4. Failure semantics

The production path fails closed when:

- the snapshot is missing;
- the snapshot has drifted;
- the current production gate is no longer valid;
- a manifest hash supplied by the caller does not match;
- the snapshot lineage cannot be resolved completely.

## 5. Definition of Done

- Render preflight requires a verified snapshot.
- Render inputs are resolved from persisted snapshot lineage.
- Manifest hashes remain stable across verification metadata updates.
- A tampered manifest hash cannot produce a render plan.
- A changed production selection requires a new snapshot before rendering.
