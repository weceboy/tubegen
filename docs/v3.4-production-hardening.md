# AutoDoc v3.4 — Production Snapshot Hardening

This update builds on v3.3 and hardens the production-bound visual lineage.

## What changed

### Persisted snapshots

Production snapshots are now represented by the existing `production_snapshots` and `production_snapshot_visuals` tables instead of relying only on an in-memory response.

Each visual selection stores:

- `scene_id`
- `scene_visual_id`
- `scene_visual_version_id`
- `source_generation_attempt_id` (nullable for upload/stock/URL assets)
- `source_asset_id`

This preserves the exact creative entity, version, provider attempt and file reference used for production.

### Snapshot gate

`server/production-snapshot.js` refuses to create a persisted snapshot unless every current scene has a selected visual whose current version:

1. is `approved`;
2. references the current scene version;
3. has a `source_asset_id`; and
4. resolves to an asset with `license_status = verified`.

A missing selection, stale visual, missing asset or unverified license is a hard gate failure.

### Reproducibility hash

The ordered visual selection payload is canonicalized and hashed with SHA-256. The hash is written to the `production_snapshot_created` audit event and returned with the snapshot.

The hash covers the concrete production lineage, not merely a visual entity name or version number.

### Auditability

Snapshot creation emits `production_snapshot_created` with the snapshot ID and reproducibility hash. The snapshot can subsequently be loaded through `getPersistedProductionSnapshot()`.

## Module API

```js
import {
  inspectProductionSnapshot,
  createPersistedProductionSnapshot,
  getPersistedProductionSnapshot
} from './server/production-snapshot.js';
```

`inspectProductionSnapshot(projectId)` performs a read-only gate check.

`createPersistedProductionSnapshot(projectId, { createdBy })` persists a gated snapshot and its visual lineage.

`getPersistedProductionSnapshot(projectId, snapshotId)` reconstructs the persisted lineage and recorded hash.
