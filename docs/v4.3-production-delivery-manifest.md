# v4.3 Production Delivery Manifest

v4.3 adds an immutable, verifiable delivery manifest on top of the v4.2 publish/release chain.

## Contract

A delivery manifest is created only for an active, verifiable production release whose publish and render lineage still verify.

The persisted manifest contains:

- project and release identity/number
- release manifest hash
- publish identity and attestation hash
- render snapshot, manifest, plan and output integrity hashes
- renderer identity and integrity timestamp
- output asset identity and storage metadata
- a canonical SHA-256 manifest hash over the persisted payload

## Idempotency

Creating a manifest for the same project and release returns the existing manifest. The first creator remains the recorded `created_by` actor.

## Verification

Verification fails closed when:

- the persisted payload no longer matches its manifest hash
- the release is missing, revoked, or has drifted
- the publish record is missing or its attestation has drifted
- the persisted delivery payload no longer matches current release/publish lineage

A revoked release therefore cannot be treated as deliverable even if the delivery manifest row itself is unchanged.

## Persistence

The `production_delivery_manifests` table is created during database bootstrap, so existing v4.2 databases receive the v4.3 table without a reset.
