# AutoDoc v3.8 – Production Publish Gate

## Purpose

A completed production render is not automatically publishable. Before a downstream publish/export step, AutoDoc must revalidate the persisted output, the snapshot manifest and the immutable render plan.

## Gate order

1. Resolve the completed production render job within the project boundary.
2. Verify the persisted render attestation against the stored `scene_assets` row.
3. Re-verify the production snapshot manifest using the job's stored manifest hash.
4. Recompute the current production render plan and require its hash to equal the job's stored `plan_hash`.
5. Only then return an `ok=true` publish decision.

## Fail-closed conditions

The gate rejects publication when:

- the render job is missing or not completed;
- the output asset is missing or belongs to another project;
- the stored output checksum is not SHA-256;
- output metadata no longer matches the persisted manifest hash;
- the output is outside `renders/<project_id>/`;
- the snapshot manifest has drifted;
- the current deterministic render plan differs from the plan captured at enqueue time.

## API

`verifyProductionPublishGate(projectId, jobId)` returns a structured decision containing the relevant snapshot, plan and output attestation hashes on success, or a stable failure code on rejection.

This gate is deliberately read-only. It never repairs or rewrites a render job, asset, snapshot or manifest.
