# AutoDoc v3.6 — Production Render Output Integrity

v3.6 extends the v3.5 production render job with a fail-closed integrity boundary between a renderer and the persisted `scene_assets` output.

## Guarantees

- Every completed production render records a SHA-256 output checksum.
- The output is bound to the immutable production snapshot and render plan through an output lineage hash.
- A second output manifest hash covers the concrete output metadata and lineage hash.
- Renderer identity is persisted for audit and reproduction.
- Integrity verification timestamp is persisted only after all checks pass.
- Render output must be a video asset and must live below `renders/<project_id>/`.
- Invalid checksums, invalid MIME types, or cross-project storage keys fail closed before an output asset is persisted.

## Persisted job fields

`production_render_jobs` adds:

- `output_checksum`
- `output_manifest_hash`
- `output_lineage_hash`
- `renderer_id`
- `integrity_verified_at`

The schema upgrade is additive and safe for existing v3.5 databases.

## Verification flow

1. Verify the production snapshot manifest.
2. Recompute the render plan and require the stored `plan_hash` to match.
3. Render the output.
4. Resolve the snapshot's exact version/attempt/asset lineage.
5. Validate output checksum, MIME type and project storage namespace.
6. Build the output lineage and manifest attestations.
7. Persist the output `scene_assets` row and integrity fields atomically.
8. Emit the completion audit event with the integrity lineage.

No invalid renderer result is promoted to a completed production render.
