# AutoDoc v3.5 — Production Render Jobs

This block turns the verified v3.4 production render plan into a durable, idempotent render job.

## Lifecycle

```text
Production Snapshot
      ↓
Manifest + Plan Verification
      ↓
production_render_jobs (queued)
      ↓ claim
running + worker lease
      ↓
renderer
      ↓
scene_assets (render output)
      ↓
completed
```

## Job identity

A production render is identified by:

- `snapshot_id`
- `plan_hash`
- `manifest_hash`

The pair `(snapshot_id, plan_hash)` is unique. Re-enqueueing the same verified snapshot returns the existing job instead of creating a second production render.

## Preflight

The job is created only after `prepareProductionRender()` verifies:

1. snapshot integrity;
2. current production selection matches the snapshot;
3. visual version is approved;
4. selected entity is actually selected;
5. source asset exists and is retrievable;
6. asset license is verified;
7. manifest hash matches the expected hash when supplied.

The worker repeats this verification immediately before rendering. A snapshot drift after enqueue therefore fails closed and cannot silently render the wrong production state.

## Worker lease

`claimProductionRenderJob()` assigns:

- worker id;
- attempt number;
- lease expiration;
- start time.

`heartbeatProductionRenderJob()` extends the lease only for the owning worker. `recoverExpiredProductionRenderJobs()` returns abandoned jobs to `queued`.

Retries are bounded by `max_attempts`. A retryable failure returns to `queued`; the final failure becomes terminal `failed`.

## Output provenance

The render result is stored in `scene_assets` and linked from the production render job via `output_asset_id`. The asset is tagged with `created_by=production-render:<job-id>` and keeps its object key, checksum, MIME type and media metadata.

The current v3.4 `scene_assets.source_type` contract does not yet have a dedicated render-output enum, so this compatibility block stores renderer output as `source_type=upload` while using the explicit production-render creator marker. A future schema revision can introduce `render_output` without changing the job lineage model.

## Audit

The block emits:

- `production_render_queued`
- `production_render_completed`

The completion event contains the snapshot id, manifest hash, plan hash and output asset id.

## Security invariant

A production renderer must never resolve its inputs from live project selection after enqueue. It consumes the verified immutable plan derived from the persisted snapshot. If the snapshot or manifest drifts, rendering is rejected with `PRODUCTION_RENDER_PREFLIGHT_FAILED`.
